# AGENTS.md

## Project shape

- This is one npm package: an OpenChamber extension, not a workspace or monorepo. The host loads `service/main.cjs`, `panel/index.html`, `panel/main.built.js`, `browsers.json`, and `icon.svg`.
- Runtime source is under `src/`: `index.ts` serves the authenticated loopback API, `actions.ts` implements browser actions, `sessions.ts`/`driver.ts` isolate one Chrome profile and debug port per agent session, and `launcher.ts` starts or adopts Chrome. The panel source is `panel/main.js` and talks through the host `serviceRequest` proxy.
- Edit `src/`, `panel/main.js`, and `scripts/`; `service/main.cjs`, `panel/main.built.js`, `browsers.json`, `service/xdg-open`, and root `xdg-open` are generated by `npm run build` and must not be hand-edited.

## Build and verification

- Install with `npm install`.
- After source or dependency changes, run `npm run typecheck` and then `npm run build`; provider tests execute the generated `service/main.cjs`, not TypeScript source, so the build must precede every test run.
- Use `npm test` for the full browser-action acceptance suite. Focused suites are `npm run test:sessions` (session isolation), `npm run test:focus` (never steals foreground focus), `npm run test:reconnect` (adopt an existing Chrome), and `npm run test:survival` (Chrome survives service stops).
- These are real-Chrome loopback tests, not unit tests: they can open visible windows and need a local Chrome. The focus/session checks use macOS `osascript`; the reconnect test directly launches `/Applications/Google Chrome.app/...`.

## Runtime invariants

- The host supplies `OPENCHAMBER_SERVICE_PORT` and `OPENCHAMBER_SERVICE_TOKEN`; the service binds to `127.0.0.1` and requires the bearer token. Do not expect `node src/index.ts` to be the host entrypoint—the host runs the built bundle.
- Actions are serialized within a session but different sessions run in parallel. A non-null OpenChamber session gets its own profile, cookies, tabs, and debug port; a null/session-less request uses the shared default profile. Tab IDs are session-prefixed and cross-session IDs must be rejected.
- Chrome windows intentionally outlive service shutdown so tabs and logins survive host idle stops and reconnects. `OPENCHAMBER_CHROME_CLOSE_ON_STOP=1` is the opt-in cleanup behavior; do not “fix” the default by killing Chrome on service stop.
- On macOS, `open -g` is the default launcher so provider windows never activate themselves; preserve this behavior and use `npm run test:focus` when changing launch or tab-fronting code.
- The default profile root is `~/OpenChamberChromeProfile`; use `OPENCHAMBER_CHROME_PROFILE` and a non-conflicting `OPENCHAMBER_CHROME_DEBUG_PORT` for manual experiments. `OPENCHAMBER_CHROME_BIN=...` overrides Chrome discovery, and `OPENCHAMBER_CHROME_HEADLESS=1` suppresses visible windows.

## Build-specific constraints

- `scripts/build.mjs` intentionally emits a self-contained CommonJS service (Playwright needs runtime `require()`), an IIFE panel bundle, and copied/linked Playwright support files. Keep the optional-peer stubs for `chromium-bidi`, `electron`, and `playwright` when changing the bundle.
- `scripts/patch-bundle.mjs` removes Playwright's signal handlers so Chrome survives service termination; it deliberately fails the build if the expected Playwright code changes. Update that patch and `test:survival` together when upgrading Playwright.
- When docs conflict with behavior, trust `package.json`, the build/test scripts, and source code; see `README.md` for installation and user-facing troubleshooting.
